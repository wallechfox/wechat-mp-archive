# 微信公众号文章 + 评论导出工具（Web 版）

**当前版本：v1.3**（2026-10-24）

一个网页界面操作的工具，**扫码即可自动登录**，可视化拉取公众号**全部历史文章**和**评论/回复**，一键导出 Markdown / HTML / TXT / PDF，图片自动下载到本地，适合给公众号做离线归档备份。

## 更新日志

### v1.3（2026-10-24）

- **模式 2 正文获取加诊断**：下载失败时不再只有一句「未提取到正文」，而是分通路汇报原因，例如 `未提取到正文（微信读书：页面无 js_content（62 字节）；短链直访：HTTP 404）`，可区分风控验证页 / 文章已删除 / 图片消息 / Cookie 失效。
- **模式 2 增加直访回退**：微信读书拿不到正文时，自动改用文章原始链接直访（免登录），成功会在日志里注明。
- **列表可选补全文章链接**：模式 2 新增「拉列表时补全文章短链」开关（默认开启），拉列表后逐篇流式读取 `og:url`（约 20KB/篇），补全链接既用于失败回退，也保存为 `output/日期公众号名公众号文章链接.txt`；可随时停止，增量写入。
- **说明**：微信读书列表是**索引快照**，原文被删除/下架的条目仍会留在列表里，这类文章任何通路都取不到正文，属于已知限制（见「常见问题」）。

- **模式 3 支持停止与重试**：下载中可用右侧「停止下载」（与模式 1/2 同一个按钮）；成功项实时从列表移除，失败项保留标红并自动勾选，可直接再次点「下载选中」。

- **列表空状态提示**：按当前模式显示不同引导文案（模式 3 提示先导入链接）。

### v1.0（2026-10-19）

## 功能特性

- **三种模式**：① 我的号（公众号后台，文章 + 完整评论）；② 别人的号（微信读书整号，仅正文）；③ 链接下载（粘贴链接 → 导入列表 → 勾选下载，免登录仅正文）。
- **扫码免复制**：微信读书、公众号后台均支持扫码登录，凭证自动填入。
- **全量历史文章**：从公众号后台「原创」列表分页拉取（`begin` 从 0 开始，翻到底），不丢第一页。
- **评论 + 回复**：抓取每篇文章的全部评论、点赞数、精选状态，以及作者回复。
- **文章链接自动导出**：模式 2 拉完列表后（开关默认开启），自动逐篇提取文章原始链接并保存为 `output/日期公众号名公众号文章链接.txt`（`标题 + 链接` 逐行）；增量写入，中途出错不丢已提取部分。
- **失败原因可辨**：下载失败时按通路给出原因（风控验证页 / 文章已删除 / 图片消息 / Cookie 失效 / HTTP 状态码），并对微信读书拿不到正文的文章自动尝试直访回退。
- **四种导出格式**：Markdown / HTML / TXT / PDF，默认全选。
- **图片可选**：「下载图片」勾掉后不下载任何图片，正文保留远程图片地址，导出更快。
- **文件布局可选**：每篇一个子文件夹，或平铺到同一目录（图片统一放 `文章文件名_files/`）。选项对三种模式均生效。
- **选择性下载**：列表支持全选 / 反选 / 勾选任意条目单独导出；下载过程可随时停止。
- **失败可重试**：下载成功的条目实时从列表移除，失败条目保留标红并自动勾选，再点一次「下载选中」即可重试。
- **评论映射缓存**：本地缓存 `mid→comment_id` 映射，重复导出越用越快、越省请求。

## 三种模式

| 模式 | 数据源 | 登录方式 | 输出 |
|---|---|---|---|
| 模式 1：我的号 | 公众号后台「原创」列表 `cgi-bin/appmsgcopyright?action=orignal` + `misc/appmsgcomment` | 扫码登录后台（自动填 token/fingerprint/Cookie） | 文章 + 完整评论 |
| 模式 2：别人的号 | 微信读书 `weread.qq.com` 接口 | 扫码登录微信读书（自动填 Cookie） | 仅正文 + 短链 txt |
| 模式 3：单篇下载 | 文章短链 `mp.weixin.qq.com/s/xxx` | 无需登录 | 仅正文（`output/读者导出_日期/`） |

> 模式 2 仅能拿到**正文**（微信读书不提供评论）；模式 3 免登录，适合零散链接的快速归档。抓取评论需要公众号后台的「留言管理」权限（即只能抓**自己**的公众号）。

## 安装

Python 3.8+（3.14 已实测）：

```bash
pip install -r requirements.txt

# 公众号后台扫码登录需要浏览器内核（约 150MB，首次运行前执行一次）
# 国内网络建议用镜像下载，速度快很多：
#   Windows (PowerShell)：
$env:PLAYWRIGHT_DOWNLOAD_HOST="https://npmmirror.com/mirrors/playwright/"
python -m playwright install chromium
#   Linux/macOS：
# PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/ python -m playwright install chromium
```

## 启动

```bash
python app.py
```

浏览器打开 **http://127.0.0.1:5000** 。

## 使用步骤

### 模式 1：导出自己的公众号（文章 + 完整评论）

1. 页面顶部选「模式 1 · 我的号」。
2. 点「扫码登录公众号后台」→ 弹出浏览器窗口 → 微信扫码确认 → 自动填入 `token` / `fingerprint` / Cookie，并识别当前公众号名。
3. 点「拉取文章列表」→ 右侧表格出现全部历史文章。
4. 勾选文章（或全选），选好格式与布局 → 点「下载选中」→ 日志实时显示进度。
5. 完成后在 `output/公众号名_日期/` 目录查看。

### 模式 2：导出别人的公众号（仅正文）

1. 页面顶部选「模式 2 · 别人的号」。
2. 填目标公众号名称，点「扫码登录微信读书」→ 自动填入 Cookie。
3. （可选，默认开启）勾选「拉列表时补全文章短链」——拉完列表会逐篇读取文章原始链接（约 1 篇/秒），用于下载失败时的直访回退，并保存为 `output/日期公众号名公众号文章链接.txt`。
4. 点「拉取文章列表」→ 右侧表格出现全部历史文章。
5. 勾选文章 → 点「下载选中」导出正文（Markdown/HTML/TXT/PDF）；失败条目会标红并给出具体原因。

### 模式 3：单篇下载（免登录）

1. 页面顶部选「模式 3 · 单篇下载」。
2. 在文本框粘贴一个或多个 `mp.weixin.qq.com/s/xxx` 链接（每行一个）。
3. 点「**导入下载列表**」→ 链接进入右侧「文章列表」，重复链接与非微信链接自动跳过，标题自动补全。
4. 在列表中勾选要下载的条目（默认全部勾选），选好格式与布局 → 点「**下载选中**」。
5. 下载失败的条目会保留在列表中并标红，可再次点「下载选中」重试；中途可点「停止下载」。

## 常见问题

- **「原创」列表 vs 全部文章**：后台「原创」列表只含**声明了原创**的文章；若公众号还有未声明原创/转载的文章，需改用后台「内容管理 → 创作 → 发表记录」接口（本工具暂未内置，可提 Issue 补充）。
- **评论列表只有「未读」的？**：`get_unread_appmsg_comment` 返回有评论的文章，本工具用 `count=50` 一次拉全（实测上限 50），覆盖绝大多数据场景；已读评论若不在该列表则无法抓取。
- **评论报错 ret≠0**：后台凭证失效（时效较短），重新扫码登录公众号后台。
- **文章列表/正文报错**：检查 token 与后台 Cookie 是否有效；或改用微信读书回退方案（模式 2）。
- **模式 3 导入后标题显示「（标题抓取失败）」**：该链接直访被风控或已失效，仍可尝试下载，失败会在列表中报错。
- **模式 2 有文章反复下载失败（微信读书报「页面无 js_content（62 字节）」）**：这类文章在微读侧只剩索引、没有正文，通常是原文已删除/下架/迁移。微读列表是**索引快照**，下线文章的条目不会立刻清理，所以列表里有、但两边都取不到正文，属于已知限制，重试无效。若某篇只是微读缺正文、原文仍在，工具会自动改走直访回退。
- **为什么列表条目数比公众号实际文章多（或有重复标题）**：微读索引按自己的收录取并累积历史，同一篇可能因不同 `originalId` 出现多条；本工具按 `originalId`+标题去重后仍可能有残留。
- **PDF 转换失败**：需系统装有 Chrome 或 Edge，用其 headless 模式转 PDF，无需额外依赖。

## 技术要点

- 文章列表分页：`begin` 从 0 开始（不是 1），翻页条件看 `totalcount`；微信读书 `offset` 是列表偏移量（不是时间戳游标）。
- 评论定位：文章正文 HTML 的 `og:url` 是短链（不含 `mid`），真实 `mid` 在 HTML 的 JS 变量 `mid:"xxx"` 里；评论接口 `content_url` 才含 `mid`，两者靠 `mid` 精确对齐（标题不可靠，如 `V7.0` vs `V6.5`）。
- 评论映射 `mid→comment_id` 长期稳定，本地缓存避免重复遍历。
- 短链提取：微信读书列表接口不返回短链，需逐篇访问正文接口取 `og:url`；本工具用**流式读取**，读到 `og:url`（响应体前约 20KB）即断连，省去后续约 2.6MB 下载。注意 `og:url` 实际是带 `__biz/mid/idx/sn/chksm` 的完整链接，不是纯短链。
- 模式 2 的取正文顺序：微信读书正文 → 页面里的 `og:url` 直访 → 报错并给出各通路原因。微信读书对部分文章只返回约 60 字节的拒绝响应，此时直访多半也会跳到验证页，日志会明确标出。
- 微信读书对部分文章的「预览」会直接塞进列表的 `title` 字段（标题 + 约 1000 字正文片段），所以导出的链接清单里可能出现多行标题，属正常现象；片段是截断的，不作为正文使用。
- 模式 3 的列表与下载队列复用模式 1/2 的表格组件：结果按 URL 回写列表，成功即移除、失败标红，导出选项（格式 / 图片 / 布局 / 输出目录）三模式共用一套后端参数。
